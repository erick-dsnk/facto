# Tech challenge catalogue (side prizes, "Best Use of X")

Source: `docs/JUNCTION_2026_CHALLENGES.md`, section "Tech Challenges", L2114-3512. Citations are `CHALLENGES.md:L<line>`. Anything the text does not say is marked "unknown".

## Summary

- 19 tech challenges. Several say outright that they stack on a main challenge (Codex L2434, Arduino L2699, Aiven L2918, CRACI L2972, Modal L3185, Oxylabs L3249); the others say "any track" or "whatever you're building", or say nothing about stacking.
- Cheapest to stack for a web/AI project, in rough order: Codex, Gemini API, Gemma, Nemotron, MongoDB Atlas, Aiven, ElevenLabs, Tiger Data, Context.dev, Oxylabs. Most are one API or one managed service. All effort ratings are my estimates.
- Best-paid prizes, all cash or credits: Modal ($2,000 cash + $3,000 credits, L3229), Codex ($10,000 API credits for 1st, L2458), Verda ($10,000 credits for 1st, L2214), Gemini API (4,000 EUR + $1,000 Google Cloud credits per member for 1st, L2534). Several MLH prizes are small hardware items, shared by the whole team in some cases.
- Must be built around the challenge (hardware or unusual process): Arduino UNO Q, Atech, Verda (if aiming to win), and CRACI (judges want more than `runs-on: craci`, L3070). Solana needs on-chain logic.
- Eligibility trap: Gemini API credits and account access are restricted to participants aged 18+ (L2518). Check the team's ages.
- Prize amounts are as given in the text. Where the text lists only "Best Overall" with no further detail, tiers are unknown.

## Notes

### Cheap to stack (software only, added to a web/AI project)

These tie to a service we would plausibly call anyway. In each case the judges' criteria reward visible, central use, so "cheap" means cheap to qualify, not cheap to win.

- **Codex** (L2420): a dev-process claim, so the team's existing agent workflow likely qualifies. Largest prize pool of the stackable ones (L2458). Judging detail is thin: unknown how entries are scored.
- **Gemini API** (L2470) and **Gemma** (L2546): drop-in model choices. Gemini needs all team members to be 18+ (L2518). Both are Google DeepMind, so one project could enter both (the text does not say whether that is allowed; unknown).
- **Nemotron** (L2588): requires the specific model and a written explanation. Rate limits (L2620) matter for agent loops. Possible overlap with Verda, which hosts a Nemotron endpoint (L2179).
- **Context.dev** (L2764) and **Oxylabs** (L3233): both feed live web data into an agent; these two are close substitutes, so pick one. Oxylabs requires showing sources (L3263), which fits a "trust" pitch.
- **Aiven** (L2905), **MongoDB Atlas** (L2226), **Tiger Data** (L2284): the database choice. One is enough per project; picking by prize, Aiven pays most (L2950-2958) and has stated criteria.
- **ElevenLabs** (L2390): cheap if the product has any voice or narration.
- **CRACI** (L2962): qualification is a one-line CI change, but placing is not (L3070). A moderate extra if the project has a repo with CI.
- **Cloudinary** (L3092): cheap only when the project handles media.

### Demand that the project be built around them

- **Arduino UNO Q** (L2687) and **Atech** (L3332): physical device is the demo. High risk given the team's low confidence in hardware. Atech's generated firmware reduces that risk somewhat (L3365), but kits are limited (L3386). Arduino additionally runs its own main challenge (L2707), so a team already working a hardware challenge could stack this cheaply; for a team on a software challenge it is a new build.
- **Verda** (L2116): the prize rewards compute-heavy work (training, rollouts, batch embedding, L2138-2142). The 10,000 USD top prize (L2214) is large, but the criteria "how much did compute let you do that you otherwise couldn't" (L2184) mean the project must truly need GPUs. Its examples tie into other challenges (robot demonstrations, AfterQuery RL, MariaDB Wikipedia, L2138-2142), so it stacks best onto a main challenge that is already ML-heavy.
- **Modal** (L3163): similar profile to Verda, with a smaller, firmer prize (L3229) and a deployed-app requirement (L3223). It lists Gemma as a hosted target (L2565), so Gemma + Modal is a natural pair for an ML-heavy project.
- **Solana** (L2358): only sensible if the project has a payments, identity or token element.
- **Entire** (L2324): changes how the team works rather than what it builds; the lowest-priority one to chase unless the workflow already fits.

### Combinations the text explicitly allows

- The text says "The same project can enter other tech challenges too" (Modal, L3185). Whether every sponsor accepts multiple entries is unknown for the others.
- Submission overheads that are easy to forget: Arduino Project Hub post (L2717), Cloudinary survey (L3110), Verda and Atech Discord posts (L2156, L3353), Nemotron text explanation in the form (L2614), Context.dev and Oxylabs endpoint notes (L2789, L3249), Gemini credits form (L2514).

### Open questions (unknown from the text)

- Whether there is a limit on the number of tech challenges one project may enter. Not stated in this section.
- Judging criteria for MongoDB Atlas, Vultr, Solana, ElevenLabs (L2226-2416) and Codex (no list, only prose at L2434): not stated.
- The four Cloudinary tools: referenced only via an external link (L3100).
- Prize details beyond "Best Overall" for the MLH challenges (MongoDB Atlas, Vultr, Tiger Data, Entire, Solana, ElevenLabs): unknown.
