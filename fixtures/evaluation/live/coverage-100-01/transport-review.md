## Fixed resources and global accounting

One global campaign allows300 Jev,160 searches and240 contents attempts;512KiB per serialized request body;512MiB cumulative serialized request bodies;16,000,000 measured/reserved input tokens;128,000 tokens reserved per pending/unknown Jev attempt; and30minutes wall time. These body-byte measurements exclude HTTP headers/TLS framing and are never treated as token estimates. Each input is separately capped at3 Jev/2search/3contents,8MiB request bodies,500,000 measured/reserved input tokens and60seconds of harness/session/terminal time. The production verification deadline remains10seconds and is unchanged.

The per-input allowances do not multiply the global authorization. Before every dispatch, the executor sums prior completed actual attempts and the current input's attempts, **including undispatched reservations**. It checks global call counts, request bytes, charged tokens and the original shared wall clock; it persists the pending attempt and rechecks after persistence before the runner can dispatch. Actual usage replaces the uncertainty reservation. A completed unknown Jev usage blocks future dispatch; returned overruns remain charged rather than erased. Fresh input sessions cannot reset global counters. The60second local window is shortened to remaining global time.

The runner's pre-dispatch callback does not advance to fetch until persistence returns. Durable checkpoints use exclusive temporary files, file fsync and atomic rename. A writer failure becomes sticky: later callbacks cannot overwrite the last good checkpoint after the first persistence error. Post-attempt checkpoints remain permitted after the dispatch deadline so the actual paid ledger can finish. The root's review found and corrected one draft post-case checkpoint that counted the just-completed input twice in its reservation-inclusive view; final tests assert every one of100 completed-case snapshots agrees with the distinct actual-attempt ledger.

## Stopping, continuing and privacy

Wrong definitive answers and ordinary operational provider errors with known usage are retained and the independent next input continues. Guarded unsafe admission/query/result spans are recorded as privacy failures; the existing observer blocks them before search dispatch, and the next independent input continues. Their failures remain in the denominator and do not earn factual success. Authentication faults, unknown usage, actual resource limits, persistence failure, unexpected provider endpoints, unfinished attempts or an actual forbidden query exposure halt the campaign. No rerun/resume is implemented.

All twenty controls must have an empty public-search allowlist. The live observer validates exact public spans, query objectives and nested highlight/contents parameters before sending retrieval requests. The executor additionally detects forbidden dispatched search/contents records, halts, and redacts any unexpectedly unsafe query string from persisted reports. This is a fault boundary, not evidence that a production privacy exposure occurred. Raw private/control text, provider prompts and keys are not placed in result reports. Original private context remains confined to the declared provider-input path; no claim of entirely on-device processing is made.

Every report retains all100 predeclared inputs and80 expected facts in its denominator, even when resource/safety stops leave some unattempted. Reports separately expose scheduled/observed/terminal counts, provider errors, guarded privacy failures, actual exposure count, actual provider attempts, request bytes, known input usage, unknown reservations and partial dollar costs. Factual correctness and independently verified selected citations are separate metrics. Existing per-input reports preserve stage times and verdict/presentation details. Aggregate response bytes and listening/device/ASR metrics remain unmeasured.

## Freeze and first-run preservation

The CLI checks clean exact Git source/commit, plan bytes, executor bytes and preflight JSON bytes before creating the exclusive hardcoded `run` directory. The preflight JSON in turn pins its own reproduction source code; code drift is rejected. Source/plan/executor/preflight freeze is reverified before each input. An existing run directory is refused, preserving its sentinel/artifacts, and a failure retains the last durable checkpoint plus a sanitized fatal receipt. Checks are read-only; they do not revive historical authorizations or historical campaigns.

The exported pure `campaignCore` is the offline-test seam. Production `execute` supplies the frozen runner, exact100-case plan, environment-only keys and durable writer. Its fresh-session loop does not load or resume an earlier campaign. Source files, protected contracts/iOS/ASR and historical held-out/private/sealed bodies are untouched.
