This proposal separates a document's reviewed authority from model judgments about the retained passage. It is a design and open corpus, not production authorization. The same document receipt must remain applicable when its contents refute the asserted value; it stores no supported/contradicted result, claim text, expected answer, or case regex.

A receipt covers one canonical document/version and bounded relation classes, under an independently reviewed issuer/keeper competence. Its identity proof and competence proof are separate from the record fields used as factual evidence. This matters for the included examples: the RFC Editor can publish the IETF's stated interpretation, not prove software compliance; Canada's consolidation is evidence of its legal rule with the publisher's stated precedence caveat; a Pulitzer register records an award outcome, not the book's publication date or merit; the ONS bulletin reports a rounded estimate for a named release/population, not exact current UK population.

The implementable trust boundary has three server-side objects:

- **ReviewedManifest:** an immutable set of receipt hashes installed through the project's review process. A retrieved page, model answer or user-supplied receipt ID cannot append to it. The corpus's proposed manifest is not such an activation.
- **VerifiedArtifact:** a private object produced by a bounded trusted acquisition or local canonical archive reader. It contains original requested/final URL, redirect history, completion time, HTTP/truncation result, raw-body digest, deterministic extraction digest and the immutable artifact handle. A source string claiming a digest, proof ID or `digestOrigin` is never this object. Those strings in the corpus are descriptions for reviewers, not a suggested runtime authorization API.
- **RecordCapabilityReceipt:** issuer/remit proof references; canonical document ID/version; document class and section/row locator; actual inspected body/extraction hashes; exact audited record-unit span/hash; permitted relation/field roles; temporal/geographic/population limits; origin lineage; review method and honest access date. All actual field values stay in the record text. Receipt values identify provenance and scope, not an answer to a claim.

A bounded application procedure:

1. Resolve a proposed receipt only inside the trusted manifest, using its content address. Validate the manifest/receipt hash and revocation state before inspecting the source. Unknown or source-created identifiers fail closed.
2. Obtain the matching VerifiedArtifact through the existing bounded acquisition path or the saved canonical artifact. Compare canonical document and version, exact trusted raw-body hash and deterministic extraction hash. The initial design requires exact canonical bytes; mutable HTML that changes must be re-reviewed. Future structured extraction could tolerate irrelevant HTML changes only after an independent parser contract verifies identity, version and every record field together; matching one convenient paragraph is insufficient.
3. Verify record-unit offsets/hash in the artifact, and bind the retained excerpt to that unit. The excerpt must contain the actual material fields/operative condition needed for the checked relation. Text elsewhere on the same page, a citation or heading alone, an obsolete OLD block, or a loosely similar paraphrase cannot borrow the unit's authority. Preserve field associations, numbers, negation, dates, units and exceptions; no model-written canonicalization.
4. Match the exact admitted proposition's relation and material circumstances to the receipt's competence and scope. This is separate from agreement. Refuting a date/value may still match; a publication date substituted for award year, current/latest substituted for a historical release, or the UK substituted for England and Wales does not. Undefined scope is not guessed.
5. Let the receipt satisfy only the independently reviewed source-qualification route for ordinary claims. Keep existing substantive-content, directness, scope, stance, confidence, citation and malformed-provider checks. Keep all health/safety/disputed-claim rules and the complete credible-conflict/dependence graph. A receipt never raises a probability, suppresses a contrary source, makes a weak excerpt substantive, or resolves conflicting records by fiat.
6. Preserve the original source URL, record version, original inspection time and lineage in audit output. A verified local byte copy can reuse an immutable historical record's original proof without a new network request, but it is not a new accessibility observation or independent corroboration. Latest/current assertions need applicable temporal proof; an old receipt is not a freshness bypass.

There is no unrestricted network reader in this mechanism. A future adapter would need a bounded canonical-artifact verification contract compatible with the existing acquisition budgets. If the available retrieval format cannot be aligned to an attested document, the capability remains unavailable. The receipt must not be granted from an Exa title, search ranking, bare HTTPS hostname or a model's original_record class alone. Failure to verify is separate from proving the underlying claim false.

The corpus intentionally includes trust-boundary negatives rather than only known failing facts. Source-controlled proof strings, forged headers and changed text fail integrity. About-page content on the same official host has no normative-document capability. An unverified mirror's declared hash fails; a trusted byte-identical saved canonical copy keeps the same origin and original timestamp. Old RFC2119 and the OLD quoted block inside RFC8174 cannot inherit the reviewed NEW clause. A historical ONS release remains valid for that release, but explicitly cannot become latest. The conflict control keeps an otherwise matching receipt and requires the downstream conflict veto; its contrary-evidence condition is synthetic, not an assertion that Canadian legal sources actually conflict.

Identity assurance remains a reviewed provenance claim, not a cryptographic issuer signature. The packet contains fresh canonical documents, role/official-status evidence, IETF and GOV.UK crosschecks, and explicitly excluded failed probes. In particular, the Pulitzer publisher's own administration/register pages identify its Board and Columbia affiliation, while two attempted Columbia paths returned404. The independent reviewer must preserve any remaining identity-assurance uncertainty. No production path should silently strengthen these proofs beyond what was inspected.
