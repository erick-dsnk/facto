# Independent retrieval-boundary feasibility review

Reviewed inputs are `record-capability-design/mechanism.md` and
`prototype-api-spec.md`. No provider execution, production edit or corpus label
inspection was needed for this review. The mechanism remains unwired.

The dated-snapshot boundary is feasible as a local, bounded proof mechanism.
The current Exa path can discover a candidate and supply bounded quote text;
it cannot independently authenticate a complete origin response, its canonical
version or its current amendment state. A title, hostname, provider status,
model `original_record` class or source-declared digest cannot fill that gap.
The proposal explicitly preserves this distinction.

Local authenticated artifacts can be matched without a fourth contents call or
an unrestricted crawler. Their original inspection time and lineage must stay
unchanged. Verification work still shares the **whole check's ten-second
deadline**, which also covers admission, retrieval and judgment; it is not a
new ten-second retrieval allowance. The existing three-contents limit cannot
be reset for identity, redirects, receipt lookup or retries. Bounded local reads
and hashing need an explicit byte/CPU deadline even when they use no provider
attempt.

Exact alignment is likely restrictive. Exa Markdown can alter whitespace,
markup, tables and mathematical notation relative to a canonical extractor.
That mismatch must yield unavailable, not a guessed alignment. All material
fields and conditions must occur within one observed contiguous excerpt of at
most 2,000 Unicode code points. A verified longer body cannot silently rescue a
missing exception, governing clause or table association outside that excerpt.
No useful-coverage gain follows from passing synthetic binding tests.

The claim-frame boundary is also still unresolved. Independently authored
frozen frames can exercise the prototype, but an untrusted source/user/model
frame cannot activate authority in production. Relation, compared value and
scope must stay distinct: opposite values for the same event can receive the
same provenance capability, while adoption/signature/entry into force, award
year/publication year, definition/compliance, historical release/current value,
and quantity/unit changes may describe different relations. Existing Jev
budgets leave no automatic extra framing call; integration needs a separate
bounded design and calibration.

Identity assurance should continue to be described as reviewed provenance,
not a cryptographic issuer signature. Opaque handles need runtime identity and
immutable private bytes, not TypeScript branding alone. No caller-supplied
path, `verified:true`, digest string, receipt ID or mutable object can become a
trusted artifact. Read-time symlink checks, bounded regular files and a
content-addressed installed manifest should be part of the local-reader tests.

## Adversarial controls for the unwired prototype

| Control | Required result |
| --- | --- |
| Canonical URL now serves changed body but an old cached quote still matches | Historical proof only; no current/latest capability |
| Same title/date and paragraph under a different document/version | Unavailable |
| Exact quote occurs in both OLD and NEW blocks with different roles | Fail closed unless one reviewed unit is unambiguous |
| Excerpt stops just before repeal, exception or material condition | Unavailable even when full archived text contains it |
| Same numeric string used for frequency versus periods/duration | Scope/role mismatch unavailable |
| Same date used for adoption, signature, entry into force or registration | Distinct relation checks; no date-only authority |
| Page-text becomes a later highlight with identical words | No refresh of original inspection time |
| Unicode composition, whitespace folding, ellipsis expansion or altered math | No proof through normalization or reconstruction |
| Caller forges a branded object or mutates exposed verified bytes | Runtime rejection or immutable private snapshot |
| Canonical body copied to an unverified mirror | No new authenticated origin or independent corroborator |
| Authenticated identical saved copy with canonical lineage | Preserve the same origin and original inspection time |
| Current-version check expired, revoked or missing | Unavailable for current/latest claims |
| Valid capability plus a credible contrary record or dependence bridge | Existing conflict/dependence veto remains active |

Offsets must use one explicit convention. UTF-16 unit offsets in the prototype
must not be confused with the wire excerpt's Unicode-code-point cap; hashes
remain over exact UTF-8 bytes. Supplementary characters and combining forms
need independent round-trip/binding controls.

## Optional bounded acquisition study, not authorization to execute

A later shadow study could use the already-authenticated new corpus's four
source classes—normative text, legal instrument, award register and reported
measure—to measure discovery and **exact alignment**, rather than factual
accuracy. Predeclare at most four searches and eight contents attempts total,
at most two contents per record, zero Jev calls, existing per-response 256 KiB
and per-request 64 KiB limits, and at most the existing per-check ten seconds.
Use only exact public claims and static neutral acquisition intent. Save actual
attempts, bytes, diagnostics and failures before interpreting outcomes.

That future study would not authenticate new snapshots through Exa, activate
receipts, solve raw-English framing or establish current accessibility. No such
calls were made for this review, and separate authorization is required before
execution. Failed/inaccessible/non-aligning declared units remain in the
denominator; supported/refuted value pairs sharing one record are not new
independent sources.
