# Runtime review of prospective two-phase initial graph completion

This is an outside-Git design review. It makes no provider calls, activates no capability, and changes no production code. The pending initial material is an exact immutable normalized inventory, with graph completion explicitly unavailable. It cannot confer source authority.

A valid completion must be a derived product of the actual same-request full judgment. The dispatch owner pins the real session/request/epoch/revision/admitted public claim and span, original raw material handle and generation, installed generation, original budget/controller/clock/acceptedAt, inherited deadline and reserved allowance. The actual serialized request is sealed before its single charged attempt. The request hash and raw-material hash are separate: the existing provider projection may omit local metadata or bound title length. Do not claim every locally retained field was seen by the model.

After the complete actual response has validated against all sent questions, the adapter privately retains the validated answers, resulting Judgment, exact request and answer hashes, original owner and material references, and attempt identity. These references must originate inside the observed ask path. A caller-supplied Judgment, response hash, refreshed input digest, serialized handle or equivalent-looking object is not an execution receipt. Test fetch injection remains an explicit test seam; it must never be described as actual-provider evidence.

The native helper may deterministically derive graph data from unchanged raw originals, empty incoming records and that actual Judgment. Require exact retained raw material and order parity. A pure helper can return derived data, but its output grants no execution authority. Only the adapter's private actual-dispatch closure may associate that data with a completed assessment handle. Prefer this over an exported generic receipt-minting function or circular trusted-producer APIs.

Keep the original pending handle and raw generation immutable. Bind a separate completed graph generation to the exact validated response and original dispatch. Do not overwrite a pre-ask input hash to suggest the completed graph was in the original prompt. Origin answers are outputs of this response; deterministic source-family links are local conservative graph facts; neither becomes a source authority credential. A completion occurs once, adds no request or allowance, and cannot be copied to a later revision, material generation or installation.

The adapter must check its opaque owner and resource identities before derivation, after synchronous derivation, before returning/using the completed handle, and at any later token verification. Currentness includes original absolute deadline and cancellation. Stale work must not install a new material generation, mutate the request/cache, emit a notification or spend a new allowance. Graph conversion failure leaves the existing pipeline baseline available according to its current behavior; it cannot promote a pending context or silently rebind a response. All risk, conflict, scope, substantive basis, citation, verdict and presentation gates remain required. No fabricated FrozenClaimFrame or core RecordCapability is introduced.

## Executable acceptance cases

1. Successful one-source and six-source full requests: exactly one charged ask; all baseline/optional answers and 15 pair-origin answers validated; completed native graph is derived from that actual Judgment; retained raw fields/order exactly unchanged.
2. Missing, malformed or swapped source/pair answer: no completed handle; no construction from a fresh caller hash.
3. Cloned, serialized, foreign-adapter or prior-dispatch receipt: reject before graph completion; an identical text/body hash is insufficient.
4. Repeat completion on the same execution: reject or return the same immutable product without reprocessing or charging; never create a second assessment authority.
5. Session cancel, newer epoch/revision, request replacement, material generation change, install retirement/reinstall, budget/controller swap and deadline equality between response and completion: reject with no cache/result/notification mutation and no extra attempt.
6. Initial raw record, raw metadata, title, exact claim or admitted span changes: original pending handle remains fixed; foreign changed snapshot cannot complete from its response.
7. A native derivation changes retained IDs, version, order or raw material: explicit parity failure; no hidden selection/reset and no reinterpretation of the prior answer.
8. Graph scope: raw copy/common-origin links remain conservative; absent/uncertain links never become independent-origin credit. Initial unknown links remain unavailable until actual completion.
9. Completed graph generation changes if actual origin answers change even when raw material does not; the old graph cannot be validated with the new response seal.
10. Cancellation during a delayed body or late response release retains adapter03's local transport abort, owned reader cleanup, single charged attempt and no late usage/result/capability/cache commit.
11. Byte limits and prototype width failures keep exact baseline serialization and all source records; no optional authority is minted from a dropped question.
12. Unchanged pending snapshot and completed snapshot remain separately inspectable for audit; original receipt/question/source evidence files and predecessor adapters are immutable.
