# Unwired typed applicability adapter 01

Executable development prototype only. Production repositories and policy are unchanged. No network or project-provider calls were made. Tests inject an in-memory fetcher into the actual Jev client and run the actual full judge. Prospective applicability36 input bodies and labels have not been opened by the adapter author; question.ts was frozen first at SHA256 5527e33e4d8f0cd191dbfb54e6602292edf0f989534fcf6b29e3c3b0da4e5233.

`captureDispatchOwner(material,{session,record,claimSlot,admittedClaim,readMaterialGeneration,readInstallGeneration,reservedJev})` captures the actual trusted runtime request and its explicit inherited reservation. It creates the reviewed seam's opaque runtime owner and a private context closing over that request's existing AttemptBudget, signal, clock and absolute acceptedAt+10s deadline. Each consume rechecks ownership. No caller ProviderContext, fresh allowance or source-defined authority is accepted.

`createApplicabilityAdapter({manifest,dispatchOwner,bindings,apiKey,fetch?})(claim)` runs one full existing judge request. Each binding contains an installed receipt alias, a private VerifiedSnapshot and an existing retained source ID. The adapter checks the real installed manifest/snapshot, canonical URL, exact proof hashes and complete reviewed material spans before adding a question. It never loads or fabricates FrozenClaimFrame. The entire retained set and private raw graph remain bound, including other versions and bridges. A later behavior-preserving selector-owned snapshot seam is being reviewed separately; this module currently consumes the reviewed outside-Git material seam rather than proposing its graph reconstruction for production.

One fixed covered/not_covered/uncertain item is added for each bound retained record. The only extra wire metadata is source/question mapping, the trusted relation enum, scope-dimension names and snapshotOnly. No actual compared field values, missing qualifier values, receipt limitations, private raw graph, assessment blobs or annotation labels are serialized. The unchanged baseline judge questions/state coexist with the item. Authority is checked before asking, not inferred from the answer.

Actual model/state/questions JSON is serialized and measured against inherited 65536 bytes before dispatch. No baseline question or companion is removed. If the complete optional augmentation cannot fit, the byte-identical baseline request executes and the optional route is unavailable. A six-source offline fixture measured 63394 baseline+1984 appendix=65378 bytes; a slightly larger valid six-source fixture falls back unchanged. A baseline already exceeding the bound fails before any HTTP attempt. The wrapper seals the exact actual fetch body and local question→retained source/excerpt hash/receipt/version map. The same attempt budget is charged and measured usage recorded. This experiment explicitly disables retries; transient errors are terminal, not silently rerun.

After the actual response, the client validates every named probability; the adapter rechecks runtime owner, deadline, claim/material/install generations and receipt retirement. The actual judgment and raw validated answers form the completed assessment. A separately parsed prototype02 Context binds exact material, raw graph, assessment and risk/conflict. Invalid or prototype-incompatible context disables optional eligibility while preserving an otherwise successful baseline judgment.

Only selected covered with probability>=.85 and ordinary-risk confidence>=.85 can create the separate private SemanticEligibility token. Missing, uncertain, not_covered, subthreshold, stale, clipped or nonordinary results cannot create one. `verifySemanticEligibility` requires the same live owner/material/manifest and exact completed assessment context. Serialization cannot recreate the token. This token **is not** prototype02 RecordCapability; its private verifier rejects it. No authority route, source-quality gate, verdict selection, scope, stance, conflict veto, origin independence, confidence threshold or production hook is changed. The token grants no verdict, temporal authorization or independent corroboration.

Temporal and representation limits remain explicit. Current/latest markers deterministically disable this dated-snapshot route, but this lexical safeguard is not a general raw-English temporal parser: implicit current meaning and ambiguous temporal scope must remain uncertain. No current/latest provenance capability is issued under any reading, because this adapter issues no RecordCapability and provides no current-version proof. Relation/dimension names cannot supply missing document identity: if a clipped operative unit does not identify its RFC/version or other material record constraint, the model must remain uncertain instead of recovering identity from an untrusted title/URL. This conservative limit may cause misses; do not add missing values after inspecting labels. A reviewed core bridge and independent semantic/full-context calibration are still required before any useful authority integration.

Offline verification: `tsx --test adapter.test.ts` and strict noEmit TypeScript, logs alongside this file. Six saved actual OPEN full-context requests were also captured without dispatch. Baseline sizes ranged36512–58205 bytes; the largest six-source pool fits three complete items and the other two six-source pools fit four (conservative real receipt-shaped descriptor sizing, not evidence that those sources possess receipts). This shows usable byte capacity without dropping companions; semantic interference remains unmeasured. Twenty-two tests cover full six-source binding, copied/serialized handle rejection, complete-unit clipping, uncertain/negative/subthreshold answers, risk, current wording, deadline/abort/material/install invalidation, retirement, same-ID companion and assessment changes, width mismatch, actual byte fallback, shared exhausted/reserved allowance, same-budget usage, per-consume owner recheck and terminal transient failure. Tests demonstrate mechanics, not model applicability accuracy or factual coverage. Future prospective36 testing must preserve authentic full companion pools, all conflicts and lineage, distinguish raw ternary accuracy from binary fail-closed eligibility, and audit every definitive citation. Binding controls must not dispatch as learned successes. No such calls are authorized by this prototype.
